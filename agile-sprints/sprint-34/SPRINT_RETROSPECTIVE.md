## 2. Retrospective Feedback (Start / Stop / Continue)

### What Went Well (Continue)
- Postman API collections allowed us to validate backend validation before the frontend UI was ready.
- Breaking acceptance criteria into Gherkin scenarios reduced miscommunication with developers.

### What Slowed Us Down (Stop)
- Stories were delivered to QA on Day 8 of a 10-day sprint, creating a testing bottleneck right before the release deadline.
- Staging database lacked realistic test user accounts, requiring QA to spend half a day generating mock data.

### Action Item for Next Sprint (Start)
- **Action:** Developers must deliver stories incrementally starting by Day 4.
- **Action Owner:** Scrum Master & Tech Lead.
